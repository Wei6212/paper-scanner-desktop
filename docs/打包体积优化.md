# 打包体积优化

## 背景

原 Windows 便携目录约 381.8 MiB，macOS 应用约 223.4 MiB。主要占用来自通用 OpenCV 和 Qt，而非业务代码或模型。本文体积均按文件内容统计，1 MiB = 1,048,576 字节，不代表文件系统实际分配空间。

## 方案与实现

- `scripts/build_opencv_minimal.py` 从 OpenCV 5.0.0 的固定提交 `40738fb16ceddb5fb3fea747585f7ce6abb0605b` 构建独立 Python 扩展，不覆盖 `.venv`。
- 保留 `core`、`imgproc`、Python 绑定，以及 OpenCV 5.0.0 必需的 `geometry`、`flann` 依赖。不打入视频、DNN、图像编解码和 HighGUI；读取、编码仍由现有 Pillow 完成。
- 保持 Release 构建和基础 SIMD；不包含额外 CPU 指令分派版本、IPP、OpenCL、KleidiCV、LAPACK 或 Eigen。不同编译配置可能影响耗时或浮点舍入，需要实测扫描结果和性能。
- `scripts/portable_dependencies.py` 从三个 Qt Python 模块和保留的插件出发，递归分析 PE 普通导入和延迟导入，只保留实际依赖的 Qt DLL。保留 `qwindows`、`qoffscreen`、`qminimal` 和软件 OpenGL 回退 `opengl32sw.dll`。
- 删除 Qt 的 QML、翻译、头文件、类型生成资料等非运行资源；删除 Pillow AVIF 扩展和 NumPy `tests` 目录，保留 `numpy.testing`。产品原有支持的图片格式保持不变。
- 两个平台打包前核对精简扩展的平台、模块清单及 SHA-256；缺失或校验失败时停止，不自动回退到通用版。分发保留 OpenCV 和 zlib 许可。
- Windows 的 `build-info.json` 同时记录原 wheel 输入和替换后的 OpenCV 构建信息；OpenCV wheel 中仅保留依赖元数据及原许可，实际执行的是独立 `cv2.pyd`。

四份模型全部保留。GUI、CLI 和图像处理算法未因体积优化而拆分或改写。

## 准备构建

除原有依赖外，需要可执行的 CMake、Ninja。可放入 `PATH`，也可安装到构建用 Python 环境；它们不会加入用户包：

```bash
uv pip install --python .venv/bin/python cmake ninja
```

取得固定版本源码，避免下载无关样例和文档图片：

```bash
git clone --depth 1 --filter=blob:none --sparse --branch 5.0.0 \
  https://github.com/opencv/opencv.git artifacts/opencv-minimal/source
git -C artifacts/opencv-minimal/source sparse-checkout set --no-cone \
  '/*' '!/*/' '/cmake/' '/include/' '/3rdparty/' \
  '/modules/core/' '/modules/flann/' '/modules/geometry/' \
  '/modules/imgproc/' '/modules/python/' \
  '/doc/CMakeLists.txt' '/docs_sphinx/CMakeLists.txt'
```

构建脚本检查源码提交及工作区状态；不要修改该源码来跳过模块检查。

## macOS arm64 构建与验证

需要 Xcode Command Line Tools，运行：

```bash
.venv/bin/python scripts/build_opencv_minimal.py
PYTHONPATH="$PWD/artifacts/opencv-minimal/darwin-arm64/python" \
  QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
.venv/bin/python scripts/build_app.py
dist/纸页扫描.app/Contents/MacOS/纸页扫描 \
  --self-test samples/手绘文档原图.jpg artifacts/体积优化应用自检
```

输出位于 `artifacts/opencv-minimal/darwin-arm64/python/`，包括 `cv2.abi3.so`、许可和 `opencv-build.json`。更换架构时使用该架构的 Python、NumPy 和编译器，并单独验证；当前记录不能证明 Intel Mac 可用。

## Windows x64 构建与验证

复用 [Windows 打包说明](Windows打包说明.md) 中的嵌入式 Python、六份固定 wheel、Zig 和 pefile。

还需 [Python 3.12.10 官方 NuGet SDK](https://www.nuget.org/packages/python/3.12.10)，将包解压到 `artifacts/opencv-minimal/python-sdk/`，确认存在 `tools/include/Python.h` 和 `tools/libs/python3.lib`。SDK 和 Python 头文件只参与构建，不进入用户包。

从 NumPy Windows wheel 解压得到 `numpy/_core/include`。已有旧便携包时，默认读取其中的头文件；全新环境可将固定 NumPy wheel 解压到独立目录，再通过 `--windows-site` 指向该目录。

```bash
.venv/bin/python scripts/build_opencv_minimal.py --target windows-x64
.venv/bin/python scripts/build_windows_portable.py
.venv/bin/python scripts/check_windows_portable.py
```

macOS 上通过 Zig 交叉编译 x64 PE，宿主 Python 仅生成绑定；目标使用 Windows Python SDK 和 Windows NumPy 头文件。原生 Windows 也可使用已配置的 CMake / Ninja / C++ 编译器，但本轮验证平台为 macOS arm64。

输出位于 `artifacts/opencv-minimal/windows-x64/python/`。两个打包脚本均可通过 `--opencv-dir` 指定该平台的其他精简构建目录。

原生 Windows 验收需覆盖 GUI 启动、中文路径、JPEG / PNG / BMP / TIFF / WebP 读取、增强、曲面展平、批量导出、JSON、退出码以及自检。DLL 静态检查不能证明动态加载、图形兼容性和扫描性能。

## 构建依据

- [OpenCV 官方构建选项](https://docs.opencv.org/doc/doxygen/html/db/d05/tutorial_config_reference.html)：支持通过 `BUILD_LIST` 选择模块及依赖。
- [OpenCV 5.0.0 imgproc 配置](https://github.com/opencv/opencv/blob/5.0.0/modules/imgproc/CMakeLists.txt)：依赖 `core` 和 `geometry`。
- [OpenCV 5.0.0 geometry 配置](https://github.com/opencv/opencv/blob/5.0.0/modules/geometry/CMakeLists.txt)：依赖 `flann`。

## 2026-10-26 构建结果

| 产物 | 原 ZIP | 精简 ZIP | 原程序目录 | 精简程序目录 |
| --- | ---: | ---: | ---: | ---: |
| Windows x64 | 143.0 MiB | 60.8 MiB | 381.8 MiB | 152.4 MiB |
| macOS arm64 | 88.8 MiB | 45.7 MiB | 223.4 MiB | 113.3 MiB |

Windows 的 OpenCV 从 112.0 MiB 降到 11.4 MiB，Qt 从 176.6 MiB 降到 62.5 MiB；macOS 的 OpenCV 从 116.1 MiB 降到 9.0 MiB。原有两个 ZIP 保留，新文件名为 `纸页扫描-Windows-x64-精简版.zip`、`纸页扫描-macOS-arm64-精简版.zip`，均提供 `.zip.sha256`。

本轮在 macOS arm64 上使用 Xcode、Android SDK 已有的 CMake 3.22.1 / Ninja 和 Zig 完成构建，未将构建工具加入应用包：

- 精简 OpenCV 下最终全量 142 项测试通过。
- 样本开启曲面展平后，与原版输出四角坐标、像素尺寸和全部像素一致；这仅代表当前样本，不代表所有输入都逐像素相同。
- macOS 最终应用自检通过，覆盖真实模型、曲面展平、GUI 后台处理和导出；独立检查五种输入格式、中文路径、纯 JSON 和退出码通过，签名完整性检查通过。
- Windows 的 106 个 x64 PE、DLL 导入、源码、四模型和入口静态核查通过；尚未进行 Windows 实机运行及性能验收。
- 两个 ZIP 的完整性检查通过。详细构建、测试和体积记录保存在 `artifacts/opencv-minimal/`，不进入 Git。

较早一轮全量测试曾出现失败及 Qt 进程崩溃，首次原因未确认；随后当前工作区的全量重跑分别为 140 项、142 项通过，最终打包应用自检通过。早期异常记录保留在 `tests-macos.log`。
